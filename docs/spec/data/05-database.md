# 05 — Database

**Covers:** Tables, ids, timestamps, foreign keys, constraints, indexes, query rules, migrations and schema versions.
**Read when:** adding or changing a table, column, index, query or migration.
**Owns:** `R-DB-*`, `AC-DB-*`.
**Index:** `docs/spec/SPEC.md` (product boundary §1, locked decisions D1–D10, routing). Section numbers are global: `§5.n` is in this file.

---

## 5.1 Conventions

- **R-DB-01** **Ids** are UUIDv7 strings generated by the application (sortable, opaque). No external reference ever
  uses a SQLite `rowid` or autoincrement value.
- **R-DB-02** **Timestamps** are `INTEGER` epoch milliseconds UTC, named `*_at`. Nullable `deleted_at` marks a soft
  delete.
- **R-DB-03** **Portable SQLite only:** types `TEXT`, `INTEGER`, `REAL`; no D1-only extension, no JSON function the
  local adapter lacks in queries on the hot path (JSON columns are parsed in the app and validated by Zod).
  Foreign keys are on (`PRAGMA foreign_keys = ON` in the local adapter; D1 enforces them).
- **R-DB-04** **Deleting a person never erases history silently.** Users are never hard-deleted while content
  references them (R-PROF-11); content foreign keys to `users` are `ON DELETE RESTRICT`. Child rows of content use
  `ON DELETE CASCADE` only where the child has no meaning alone (a thread's comments when an admin purges the thread).

## 5.3 Constraints and indexes

- **R-DB-05** Unique: `users.auth_email`, `invites.email`, `info_pages.slug`, `(chat_messages.sender_id, client_nonce)`.
- **R-DB-06** Indexes: `posts(is_pinned DESC, last_activity_at DESC, id DESC)` · `posts(last_activity_at DESC, id DESC)`
  · `comments(post_id, created_at, id)` · `media(album_id, created_at DESC, id DESC)` ·
  `media(owner_id, created_at)` · `media(taken_year, created_at DESC, id DESC)` ·
  `chat_messages(room_id, created_at DESC, id DESC)` ·
  `chat_messages(created_at)` · `users(status, display_name_norm)` · `invites(status, email)` ·
  `upload_reservations(state, expires_at)` · `rate_events(bucket, at)` · `audit_events(created_at)`.

## 5.4 Query rules

- **R-DB-07** Every list query has a `LIMIT` (≤ 50, defaults per screen) and keyset pagination on its index columns
  (`(last_activity_at, id) < (?, ?)`); no `OFFSET` paging and no `COUNT(*)` over a whole table on a page request
  (`comment_count` and `storage_usage` are maintained counters).
- **R-DB-08** Multi-step state changes run in one D1 `batch` (a transaction on the local adapter): reservation +
  usage counter, media row + usage commit, comment + `last_activity_at` + `comment_count`.
- **R-DB-09** Inputs are validated by Zod at the route boundary; SQL is parameterized through Drizzle; no string-built
  SQL.

## 5.5 Migrations and schema version

- **R-DB-10** Migrations are numbered plain SQL files in `migrations/` (`0001_init.sql`, …), generated by
  `drizzle-kit` and reviewed by hand, applied by `wrangler d1 migrations apply` (through `scripts/cf.mjs`) remotely and
  by the same files locally. Each records `schema_version` in `schema_meta`.
- **R-DB-11** Migrations are additive where possible. A destructive step (drop, narrowing rewrite) is its own
  migration, named `*_destructive.sql`, and `preflight` refuses to apply it until a verified backup newer than the
  last deploy exists (INV-7, R-OPS-12).
- **R-DB-12** Importers accept backups from the current and the two previous released schema versions; CI restores a
  fixture backup of each into the current schema (R-BAK-13).
